# 渐进阅读学习代码库

让用户能沿一个真实动作追踪代码，解释输入、调用、返回、状态变化与最终输出，并用运行证据检验理解。适用于学习已有项目；普通功能开发或故障修复任务不必套用整套教学过程。

## 先建立项目与学习上下文

- 先读适用的 AGENTS.md、项目说明、依赖与启动入口，确认当前代码及未提交修改，再选择少量相关源码。不要按目录逐文件朗读。
- 从当前对话判断用户基础、目标和停留位置；已有进度则接着讲，不从头重开。只有影响下一步的信息缺失时才询问。
- 区分用户希望听解释、自己动手、由助手修改或接受考核。用户希望自己实现或仅听讲时，不代写到项目中；用户授权代改时按其范围执行。
- 首次给出简短学习路线：整体架构 → 一条真实执行链 → 关键模块 → 验证与评估 → 工程复盘。依据项目与用户目标裁剪，而不是要求完成固定章节数。

## 围绕真实动作逐步深入

1. **整体架构**：说明各模块负责什么、如何通信、什么数据被保存。区分代码已实现、文档计划和本次已验证。
2. **执行入口**：选一次用户动作、命令或事件，找到真正触发业务的入口。区分定义、注册、实例化和调用。
3. **调用与返回**：沿调用者、被调用者、框架回调追踪。明确“谁在等待谁返回”“返回后接着执行哪一行”；遇到框架调度，指出注册位置和实际执行位置。
4. **参数与数据**：给关键变量标出来源、类型、最小示例和当前值。区分请求数据、局部变量、工作流状态、数据库记录与页面状态；同名变量不默认是同一个对象。
5. **状态与失败**：解释分支、停止条件、异常传播、事务边界与恢复入口。并发路径使用偏序或并行表达，不强行画成唯一时间顺序。
6. **从结果回看**：跟到最终输出、持久化与显示位置，确认中间事件、最终状态和用户可见结果分别证明什么。

选用与当前问题直接相关的源码片段，引用当前文件位置。若代码已改动，重新核对，避免拿过期行号或历史结果讲解。

## 每轮教学的推进方式

- 一轮聚焦一个主要概念或一个完整小行为；先回应用户当前理解，再推进一个相邻步骤。
- 先说预期行为或可观察结果，再结合代码解释原因。需要时用输入 → 中间数据 → 输出，补充调用栈或时序。
- 暴露基础概念缺口时，用短小的同构例子补齐，再回到原项目。不要把局部疑问扩张成整门语言课程。
- 明确纠正具体误解，并保留回答中正确的部分。不要因单次数值答对、代码复制成功或页面显示正常就宣布已经掌握。
- 适量用预测、追踪或复述检查理解；用户要求跳题、减少判断题、只听思路或停止动手时，立即切换为讲解或完整案例，不把答题当继续课程的门槛。
- 图示仅在有助于理解关系或随执行变化的值时使用。紧凑的静态图、表或调用栈足够时，不另造复杂交互。

需要讲清回调、异步顺序、状态与事件、类型变换、历史数据或评测指标时，按需读取 [教学模式与案例](references/teaching-patterns.md)，不要每次加载全部案例。

## 从阅读过渡到运行与实践

- 根据模块选择验证：CLI、API、界面、定向测试或受控模拟。先确认已有服务和运行方式，避免为教学重复启动会改变共享状态的服务。
- 动手任务给出具体目标、修改范围、正常与边界验收条件。先让用户定位或提出方案；卡住时给准确位置、最小可行改法及解释，不反复只让用户猜。
- 为新字段或行为考虑已有数据是否缺失、合法的零值、重复数据，以及代码和构建产物的生效方式。只检查与本次变更相关的边界。
- 检查显示结果时区分新旧任务、当前选中对象及实际接口返回；看到占位符不立即归因于算法错误。
- 模拟、函数级检查、界面观察与完整联调分开报告；不把既有测试记录写成本轮重跑结果。先使用足以回答问题的本地证据。
- 学习说明不自动变成真实外部调用、部署或 Git 操作；这些动作依照用户当前授权进行。

## 按项目选择深入模块

不要求每个项目都讲下列所有内容：

- 数据如何导入、解析、切分、索引与保留来源。
- 算法如何处理一次输入：中间数据结构、排序、边界与成本。
- 工作流如何路由、循环、累计状态、停止及恢复。
- 外部服务的请求、响应解析、错误分类、重试和用量记录。
- 数据层的 SQL 构造、执行、事务、持久化与快照。
- 页面或客户端的数据获取、异步防覆盖、响应式更新与历史兼容。
- 测试为何选择这些行为，质量指标检查什么，以及实验能支持多大的结论。
- 配置、依赖、运行进程、构建产物与启动命令分别从何而来。

## 复盘、考核与学习记录

- 用户询问进度时，说明已覆盖内容和剩余阶段；估计覆盖度不等于掌握度评分，不凭空精确报百分比。
- 用户希望考核时，优先采用一个新场景的完整追踪、故障定位或小改动，明确评价标准。给提示后将结果记为指导完成；没有做独立考核就不授予独立开发结论。
- 用户不希望动手或答题时，使用完整示例复盘，不强行恢复之前的练习要求。
- 按需保存学习摘要或断点：当前目标与项目版本、已读模块、用户实际操作、观察结果、误解与澄清、仅讲解内容及下一步。不要把过期偏好永久固化。
- 简历素材区分项目能力、用户实际贡献、辅助验证、历史记录和未实施计划；用样本、配置与指标口径约束效果表述。
- 学习总结或 skill 的生成，不包含自动提交仓库的授权；用户要求 Git 操作时，只提交约定文件，保留其他工作区修改。
