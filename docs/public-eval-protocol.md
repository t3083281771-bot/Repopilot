# 公开代码定位问答评测协议

本协议对应 `eval/datasets/public-code-qa.json`。数据集类型固定为
`public-code-qa`：根据真实公开仓库的固定版本源码编写行为理解与定位问题。
这些题目不是从公开 Issue 采集的故障报告，也没有补丁、执行测试或修复成功标注。

## 数据来源与版本

- `psf/requests`：以发布版本 `v2.32.5` 选择代码范围。
- `pallets/flask`：以发布版本 `3.1.2` 选择代码范围。
- `pallets/click`：以发布版本 `8.2.1` 选择代码范围。

发布标签仅用于选版。每个 case 的 `ref` 必须填写实际导入并核验过的 40 位
Git 提交 SHA；评分时使用该 SHA，不能使用会移动的分支或标签。数据集顶层的
`repositories` 记录发布标签、固定 SHA 及公开来源 URL。标注只能根据这些快照的
实际文件与函数完成；下载失败不能用记忆、当前网站版本或其他本地项目代替。

## 题目组成与标注

每库 10 题，共 30 题；每库 2 题 `dev`、8 题 `test`，合计 6/24。
题目覆盖参数、条件分支、异常转换、状态传递和跨函数定位。每库至少 5 题
不在问题中直接给出目标函数或方法名，减少直接查找符号的捷径。
初版实际有 20 条不直接给出目标符号的问题；每库开发集包含一条符号引导题和
一条行为描述题。全部 30 题共有 40 处已核对的源码函数范围。

每条记录采用以下字段：

```json
{
  "id": "requests-01",
  "split": "dev",
  "question": "根据实际固定源码编写的问题",
  "files": ["真实仓库相对路径"],
  "symbols": ["与当前解析器完全一致的函数或类方法名"],
  "source": "https://github.com/owner/repo",
  "ref": "40位已核验提交SHA",
  "question_style": "behavioral 或 symbol-guided",
  "exposes_target_symbol": false,
  "annotation_notes": "具体控制流、参数或异常依据；可包含定位局限",
  "gold_evidence": [
    {
      "path": "真实仓库相对路径",
      "symbol": "真实符号名",
      "start_line": 1,
      "end_line": 2
    }
  ]
}
```

上面的路径、符号与 SHA 是字段说明，不是可使用的题目标注。正式数据不得保留
占位值。`gold_evidence` 的行号为固定快照中 1-based、首尾均包含的函数范围。
多处代码共同解释问题时列出多个合理定位，不把单个修改文件当作唯一正确根因。
题目不声称库存在缺陷；正常行为与有意的边界处理也可以作为定位对象。

拟题采用源码逐题阅读、辅助起草和核对的方式；没有独立双人标注或一致性评估。
冻结前检查文件存在、AST 符号及范围匹配、相应索引中有可检索片段。AST 检查仅能
确认定位存在，不能替代对问题语义与控制流的核对。

## 评分与执行

使用项目评测器，保持数据版本、索引版本、检索参数与 embedding 配置相同：

1. 对比 `bm25`、`vector`、`hybrid`、`hybrid_rerank`。
2. 首先去重，再计算前五个文件或 `(path, symbol)` 的命中。
3. `file_hit_at_5` 表示任一标注文件命中；`file_recall_at_5` 表示标注文件覆盖比例。
4. `symbol_hit_at_5` 表示至少命中一个属于标注文件的标注符号；它不是所有必要
   函数都定位成功的指标，跨函数题还需查看逐题结果及文件召回。
5. 单独记录索引导入与检索耗时；检索耗时包含查询向量生成，不包含回答生成。

当前符号指标按名称匹配，不检查片段与 `gold_evidence` 行号的重叠。Click 中
存在与实际实现同名的 `typing.overload` 声明；只命中声明也可能被计为符号命中。
因此该指标是粗粒度定位信号，不能替代对实际实现体和解释依据的人工核对。

`hash` embedding 是词法演示向量，`hybrid_rerank` 当前是词法启发式重排。
使用它们得出的结果不能表述为语义向量或学习型重排模型的性能。

端到端比较是可选项，比较 `single` 与有预算的 `agent`，应保留全部调用与失败
重试的 Token 统计、轮数和工具次数。失败请求没有提供方 usage 时必须标注估算。
候选引用命中不能自动证明解释正确；引用有效性、解释是否受证据支持仍需单独核对。
演示模型只证明流程和引用能够运行，不用于证明大模型分析能力。

## 冻结、开发集与局限

- 开发集用于检查实现与调整参数，测试集用于冻结后一次正式报告。报告保存原始
  数据文件 SHA-256；若根据测试表现改题、改标注或调参，必须重新标记版本并说明。
- 当前划分只隔离题目，三个仓库同时出现在开发集与测试集，**没有仓库级泛化验证**。
  同库问题也可能共享模块、术语或控制流；不能把 24 题当作相互独立的大样本。
- 题目由阅读待测代码后编写，词汇和题型可能偏向可检索内容；没有自然用户请求
  的分布代表性，也没有独立标注一致性验证。
- 公开热门仓库可能已出现在模型训练数据中，不能排除预训练污染。固定提交能
  保证版本复现，不能消除模型记忆。
- 本集没有覆盖任意大型仓库、其他语言、不足以回答的问题或恶意仓库内容。
  不据此宣称拒答可靠性、安全性或生产级覆盖率。
- 这些题目是源码理解与定位问答。结果只能写成“在 3 个固定版本公开 Python
  仓库、24 个测试问题上的定位表现”，不能写成“解决了 24 个真实 Issue”、
  “补丁通过率”或“SWE-bench 成绩”。

扩展到真实 Issue 时，应另外建集，固定故障发生时的基础提交及信息时间截断，
排除后续修复提交、补丁和解答性评论，并另行设计修复验证；不能更改本集名称
或来源说明来替代该工作。
